# Rasta Pyramid Factory v0.1.5 TEST

**Status: BUILT / SELF-TESTED - 2026-11-05 - waiting for Jim's live test in ArcGIS Earth**

v0.1.5 changes one thing: the **MBTiles -> TPKX stage**. Everything before it (flat/georaster detection, staging, overviews, headless QGIS rendering, verified MBTiles, synthetic parking at 30 N 80 W, heartbeat) is the v0.1.3 LIVE-PROVEN baseline, unchanged.

## Why

Jim asked for Rasta's TPKX output to be checked against the converter the ArcGIS Earth Flight family uses today, **mb2tpkx 1.1** ([QGIS-Mbtile-to-ArcGIS-Earth-TPKX](https://github.com/Jim-dc95811/QGIS-Mbtile-to-ArcGIS-Earth-TPKX)), whose packages are proven in ArcGIS Earth and ArcGIS Pro (its JSON templates and bundle header were taken from a TPKX that ArcGIS Pro itself made). Reference file: Jim's `demo_lon_41.tpkx` (London, Z6-Z18, 11,821 tiles), made by mb2tpkx and flown in ArcGIS Earth, plus its source `demo_lon_41.mbtiles`.

## What was different in the v0.1.0 converter

Measured with `tools/tpkx_compare.py` (ArcGIS-Earth-Unlocked toolbox), same MBTiles in, layer by layer. The tile images themselves were always copied correctly (all 11,821 identical); the differences were in how they were described and packed:

| Part | v0.1.0 (old) | Proven reference (mb2tpkx / ArcGIS Pro) |
|---|---|---|
| Bundle header: record count | 16384 | 0 |
| Bundle header: legacy field at byte 48 | 16 | 0 |
| Bundle header: max record size | largest tile | 131092 (or the largest tile, if bigger) |
| Index value for a missing tile | 0 | **4** (Esri's empty-slot value) |
| root.json tileImageInfo | PNG/JPEG, quality 0/90, no bandCount/lercError | MIXED, 75, bandCount 1, lercError 0 |
| root.json levels (LOD resolution/scale) | recalculated | Esri's published values, copied exactly |
| Extent | from the MBTiles 'bounds' text | from the finest-level tiles actually present |
| iteminfo.json | tags as a list, snippet/summary text, created time | tags "", empty snippet/summary, created 0 |
| Zip entries | Python defaults (Unix origin when made on Linux) | Windows/NTFS-style entries, stored, as ArcGIS writes them |
| Thumbnail | grey 200x133 | 300x200 picture of the map (plain 300x200 if Pillow is missing) |

Esri's published spec ([tile-package-spec](https://github.com/Esri/tile-package-spec), root.md) allows MIXED as a format, fixes packet size 128 and esriMapCacheStorageModeCompactV2 - all as in the reference.

## What v0.1.5 does

- New `System Files/MBTiles_to_TPKX_v0_3_0.py` (standard library only, as before; same command line, same progress lines, same exit codes) writes exactly the mb2tpkx 1.1 structure. Writes to `<name>.tpkx.partial` and renames only on success.
- `RASTA_PIPELINE.py` now calls it; `MBTiles_to_TPKX_v0_1_0.py` is removed from the package (it stays in Git history).
- `RPF_SELF_TEST.py` checks the new converter's fingerprint **and** converts a small test MBTiles and checks the parts the old converter got wrong (header fields, missing-tile value 4, tileImageInfo, Esri LOD values, iteminfo, zip entries). Run against the old converter, it fails on all of them.

## Verified here

- London `demo_lon_41.mbtiles` -> v0.3.0 vs Jim's flown `demo_lon_41.tpkx`: **0 structural differences, all 24 bundles byte-identical** (with and without Pillow).
- Bryceville 7-layer MBTiles (PNG, 6,461 tiles): v0.3.0 vs mb2tpkx 1.1: **0 structural differences**.
- Converter run through Rasta's own `_run_converter` + `inspect_tpkx`: progress reaches the GUI, output accepted.
- Self-test: PASS.
