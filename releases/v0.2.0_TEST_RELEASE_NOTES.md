# Rasta Pyramid Factory v0.2.0 TEST - Photo mode

**Status: BUILT / SELF-TESTED - 2026-11-06 - waiting for Jim's live test.**

## Why

Jim (2026-11-06): *"could you write a script that emulates what this program does without having to use the QGIS engine?"* and *"a 260 MB jpg turned into a 1.7 GB tpkx"*.

A flat picture is parked by Rasta at an exact spot (centred on 30 N 80 W, 1 picture pixel = 1 Web Mercator metre, lined up with the map grid), so its tiles need no reprojection - each tile is a patch of the picture, scaled. QGIS was doing heavy work for a cut-and-resize job, and it saved every tile as PNG (lossless), which multiplies the size of an already-compressed photo.

## What v0.2.0 does

- **Photo mode** (`System Files/RPF_PHOTO_TILER.py`, Pillow): flat pictures are tiled directly - **no QGIS needed** for photos. Same tile addresses and the same placement as the QGIS route (tile set = `estimate_synthetic_tiles`; picture edge within half a pixel of the synthetic bounds), so coordinates, gates and objects stay valid.
- **Mixed tiles:** JPEG (quality 85) for tiles fully inside the picture, PNG with transparency for tiles on its edge (so the ocean shows around it). TPKX packages say MIXED, as Esri's own do.
- **Real map rasters** (GeoTIFFs with coordinates) keep the QGIS route unchanged. Without QGIS installed, Rasta reads pictures with Pillow and recognises GeoTIFF coordinate tags.
- **Settings** (`System Files/Rasta_Config.ini`, new `[PHOTO]` section): `engine = photo` (or `qgis` for the v0.1.x route), `tiles = mixed` (or `png`), `jpeg_quality = 85`.
- **Launchers** install Pillow automatically the first time (same pattern as mb2tpkx).
- Window: the recipe line shows *PHOTO MODE - no QGIS needed* for photos; new stage *PHOTO MODE PYRAMID*.

## Measured here - Jim's Kings_reach_panorama_1.jpg (50,000 x 12,006, 261 MB JPEG)

| | v0.1.6 (QGIS, Jim's PC) | v0.2.0 photo mode (this workspace, 2 CPUs) |
|---|---|---|
| Tiles Z0-Z18 | 35,216 | **35,216** (same set) |
| Build time | 8 min 46 s | **about 48 s** |
| TPKX size | 1,771 MB | **442 MB** (MBTiles 465 MB) |
| QGIS needed | yes | **no** |
| Peak memory | - | 3.0 GB (about 5 bytes per picture pixel) |

Tile checks: 15 neighbouring zoom-17 tiles stitched with no seams; zoom-12 picture complete; repeat runs give byte-identical tiles. Pipeline rig: TPKX, Both and cancel (stops at once, temp cleaned) all pass with QGIS absent; the QGIS route still runs unchanged with `engine = qgis`. Self-test adds photo-mode checks (tile count, JPEG/PNG mix, GeoTIFF detection, converter acceptance).

## Memory

Photo mode opens the whole picture: about 3 GB for a 600-million-pixel photo, about 6 GB for 1.2 billion (Kings Reach 2). If a PC runs short, Rasta says so; `engine = qgis` uses the QGIS route instead.
